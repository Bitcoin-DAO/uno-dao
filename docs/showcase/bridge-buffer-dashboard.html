BB dashboard — MVP

Pulls per-worker hash-share data for a CKPool solo account, then splits a weekly treasury payout across workers in proportion to hash contributed. Weekly measurement window, weekly disbursement.

1 · Load worker data

Enter the Bitcoin address this account mines to. This tries a direct fetch from raw.stats.ckpool.org — most browsers block that cross-origin, so a manual paste fallback is provided below either way.

2 · Weekly treasury payout

Total amount the Bridge Buffer reserve is paying out this week, split across workers by their share of hashrate7d.

3 · Split

Load worker data above to see the breakdown.

On the live-fetch step: CKPool's stats endpoint is a bare server with no cross-origin headers, so a browser fetch from this dashboard will very likely fail with a CORS error — that's expected, not a bug. The production version of this needs a small server-side poller (a good fit for the Cloudflare Worker + D1 + Cron setup already planned for Sun to Sats) that fetches the CKPool JSON on a schedule, stores a weekly snapshot per worker in D1, and serves that stored history to this dashboard same-origin. That also solves a second problem the live endpoint can't: CKPool only exposes the current rolling window, not a historical archive, so weekly figures have to be captured and stored as they happen, not reconstructed after the fact.
Field used: hashrate7d per worker, matching the weekly measurement window. Workers with no reported hashrate7d are shown with a zero share rather than excluded, so a quiet worker is visible, not silently dropped.
Bitcoin Bridge Buffer — internal MVP tool. Not for production payout decisions until the Cloudflare-backed history store described above is in place.
